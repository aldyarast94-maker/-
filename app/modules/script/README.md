# script

**Задача:** картинка страницы → сценарий: реплики с рамкой, текстом, языком, типом, говорящим, эмоцией

- Публичный вход: `ScriptReader` (`src/main/kotlin/com/npcknows/bubblecast/script/ScriptReader.kt`).
  Другие модули используют только его.
- Всё остальное — в пакете `internal/` с видимостью `internal`.
- Зависит от: shared, api_client.
- Вид: `bubblecast.android`.
- Тесты: `src/test/`.

## Поставщики

- `internal/providers/local/` — на телефоне, без сети (Базовый).
- `internal/providers/cloud/` — через `api_client` (Профи).

## Порядок чтения (готово)

`internal/ReadingOrder` — свой геометрический алгоритм: рамки собираются в ряды по высоте, ряды сверху вниз,
внутри ряда справа налево (манга) или слева направо (комикс); вебтун — сверху вниз.
Готовые решения не подошли: Kumiko и детектор inkwell — AGPL, Magi — только для исследований.

## Поставщик local: как работает (этап 2, готово)

`internal/providers/local/`:
1. `BubbleDetector` — рамки текста (в пузыре / вне пузыря); длинная лента вебтуна режется на почти квадратные куски.
2. `ReadingOrder` — порядок рамок по виду книги.
3. `LineFinder` — строки внутри рамки (DB); куски одного ряда склеиваются в строку.
4. `TextRecognizer` — текст строки (CTC). Строки с уверенностью < 0.6 отбрасываются (мусор).
5. `Heuristics` — язык (кириллица/латиница), тип (речь / звук / текст автора), простая подача по знакам.

Картинку декодирует `image/AndroidImageDecoder`; в тестах — `RawRgbDecoder` (пиксели из `tools/make_test_pages.py`).
Тесты с моделями запускаются с `BUBBLECAST_MODELS=<папка моделей>`, без неё пропускаются.

Известное: модель путает одинаковые по виду с/С, т/Т, ы/Ы — регистр чинит text_prep.
