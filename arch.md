# arch.md — карта проекта

> Статус схемы: **ЧЕРНОВИК — ждёт ОК владельца.** Пока статус не «УТВЕРЖДЕНО», код не пишется.
> Эту карту меняют только с согласия владельца. Правила работы — `.claude/skills/arch-rules/SKILL.md`.

## 1. Что строим

Приложение для телефона, которое **озвучивает мангу, комиксы и манхвы, пока ты читаешь**:
находит реплики на странице, понимает, кто говорит и с какой эмоцией, и читает их разными голосами,
как профессиональная озвучка. Звук идёт вслед за тем, что ты сейчас видишь на экране.

Форматы чтения:
- **манга** — страницы, кадры справа налево;
- **комикс** — страницы, кадры слева направо;
- **манхва / вебтун** — одна длинная лента сверху вниз.

## 2. Три закона фундамента

1. **Один модуль — одна задача — одна папка.** Задача модуля описывается одним предложением
   «берёт X → отдаёт Y». Если нужно слово «и» — это два модуля.
2. **Общее живёт в одном месте.** Код, нужный двум и более модулям, лежит только в `shared/`
   своей части (приложение или сервер). Копировать код между модулями **запрещено** —
   нужен второй раз → переносим в `shared/`.
3. **Данные между приложением и сервером описаны один раз** — в `contracts/`.
   Код типов для Dart и Python генерируется из них и руками не правится.

## 3. Стек (решение и почему)

| Часть | Выбор | Почему |
|---|---|---|
| Приложение | **Flutter (Dart)**, сначала Android, потом iOS | один код на обе платформы, хороший просмотр картинок и звук |
| Сервер | **Python 3.12 + FastAPI** | весь ИИ (зрение, распознавание, синтез речи) живёт в Python |
| Понимание страницы | **Vision-LLM (Claude)** через адаптер | за один взгляд видит порядок реплик, кто говорит, эмоцию по лицу и контексту |
| Синтез речи | **адаптер провайдера** (облачный или свой на GPU) | провайдер меняется без переделки остального |
| Контракты | **JSON Schema** → генерация Dart и Python | одно описание данных, без копий |
| Хранилище | файлы + SQLite (сервер), локальный кэш (телефон) | просто, хватит на старт |

Тяжёлая работа — на сервере: на телефоне нельзя держать ключи API, а качественная эмоциональная
русская речь требует GPU. Телефон показывает, следит за позицией чтения и играет звук.
Уже озвученные главы кэшируются на телефоне и потом работают без сети.

## 4. Как это работает (поток данных)

```
 ТЕЛЕФОН                                   СЕРВЕР
 ───────                                   ──────
 library ─(книга)─► reader ─(страницы)─► api_client ══► api ─► pipeline
                       │                                         │
                       │ где сейчас глаза                        ├─► pages       картинка → страница с id и хешем
                       ▼                                         ├─► understand  страница → сценарий реплик
                   narration ◄══(озвучка)══ api_client ◄══ api ◄─├─► characters  «говорящий» → стабильный персонаж книги
                       │                                         ├─► cast        персонаж → голос
                       ▼                                         ├─► text_prep   текст → произносимый текст
                   динамик                                       ├─► tts         реплика + голос + эмоция → звук
                                                                 └─► cache       уже сделанное не делаем второй раз
```

Сервер обрабатывает страницы **на несколько вперёд** от того места, где ты читаешь,
поэтому к моменту, когда ты дошёл, звук уже готов.

Два режима синхронизации (модуль `narration`):
- **«Я веду»** — ты листаешь сам, звук догоняет видимые реплики;
- **«Веди меня»** — звук идёт сам, экран плавно прокручивается за ним.

### Устройство любого модуля

```
modules/<имя>/
├─ README.md        ← задача одним предложением, вход, выход, от кого зависит
├─ <имя>.dart | api.py   ← ПУБЛИЧНЫЙ вход — другие модули импортируют только его
├─ internal/        ← всё остальное, снаружи не импортируется
├─ providers/       ← (если есть внешние сервисы) по одному файлу на провайдера
└─ tests/
```

## 6. Модули

### Приложение (`app/lib/modules/`)

| Модуль | Задача (берёт → отдаёт) | Зависит от | Статус |
|---|---|---|---|
| `library` | файлы пользователя (CBZ/ZIP/PDF/картинки) → книга со списком страниц | shared | план |
| `reader` | книга → показ страниц на экране + текущая видимая область | shared | план |
| `narration` | видимая область + готовая озвучка → что и когда играть, подсветка реплики | shared, api_client | план |
| `voices` | персонажи книги → экран выбора голоса каждому | shared, api_client | план |
| `settings` | действия пользователя → сохранённые настройки | shared | план |
| `api_client` | запросы модулей → обмен с сервером по контрактам | shared | план |

### Сервер (`server/src/modules/`)

| Модуль | Задача (берёт → отдаёт) | Зависит от | Статус |
|---|---|---|---|
| `api` | HTTP-запросы → вызовы pipeline и ответы по контрактам | shared, pipeline | план |
| `pipeline` | страница → готовая озвучка, **только вызывает модули по порядку**, своей логики нет | shared, все ниже | план |
| `pages` | загруженная картинка → страница (id, хеш, размер, тип ленты) | shared | план |
| `understand` | картинка страницы → сценарий: реплики с рамкой, текстом, типом, говорящим, эмоцией | shared | план |
| `characters` | «говорящий» со страницы → стабильный персонаж книги (один и тот же через главы) | shared | план |
| `cast` | персонаж → голос (подбор по полу/возрасту/характеру, выбор пользователя важнее) | shared | план |
| `text_prep` | текст реплики → произносимый текст (ударения, ё, числа, звуки вроде «БА-БАХ») | shared | план |
| `tts` | произносимый текст + голос + эмоция → аудиофайл | shared | план |
| `cache` | ключ (хеш страницы/реплики/голоса) → готовый результат или «нет» | shared | план |

Типы реплик в сценарии: `dialogue` (речь), `thought` (мысль), `narration` (текст автора),
`sfx` (звук), `sign` (надпись на фоне — по умолчанию не читается).

## 7. Правила зависимостей

- Модуль импортирует только **`shared/`** и **публичный вход** модулей из колонки «Зависит от».
- Модули одного уровня (например, `tts` и `cast`) друг о друге **не знают** — их связывает только `pipeline`.
- Циклы запрещены.
- `shared/` не зависит ни от одного модуля.
- Приложение и сервер не делят код — они делят только `contracts/`.

## 9. Открытые вопросы к владельцу

1. **Откуда комиксы?** Предлагаю этап 1 — свои файлы во встроенной читалке. Чтение поверх других
   приложений (захват экрана на Android) — отдельный модуль-источник позже. Согласен?
2. **Язык.** Озвучиваем только русский текст, или нужен перевод (англ./кор./яп. → рус.)?
   Перевод — это отдельный модуль `translate` между `understand` и `text_prep`.
3. **Синтез речи.** Облачный провайдер (быстрее старт, платно за символы) или свой на GPU
   (например, через твой ComfyUI)? Адаптер позволяет начать с одного и перейти на другой.
4. **Для кого.** Только для тебя или в магазин приложений? От этого зависят вход, оплата и нагрузка.
